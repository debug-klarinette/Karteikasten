# Fabrikplanung · VL 09 – Digital Tools in Factory Planning

### How does VDI 4499 define the "Digital Factory"?
- [x] The umbrella term for a network of digital models, methods and tools (incl. simulation and 3D visualization), integrated through continuous data management, for holistic planning, evaluation and continuous improvement of the real factory in connection with the product
- [ ] A single CAD program used to draw the factory floor plan
- [ ] The physical prototype of a factory built before construction
- [ ] The ERP system used for order processing
> Explanation: Per VDI 4499 the Digital Factory is a comprehensive, data-integrated network of digital models, methods and tools (including simulation and 3D visualization) aiming at holistic planning, evaluation and continuous improvement of all essential structures, processes and resources of the real factory together with the product.

### How do "Digital Factory" and "Virtual Production" relate?
- [x] Virtual Production is the comprehensive, experimentable digital representation of production (the vision); the Digital Factory provides the models/methods/tools and serves as the link between real and virtual production
- [ ] They are exact synonyms with no difference in focus
- [ ] Virtual Production is a physical mock-up; the Digital Factory is software
- [ ] The Digital Factory replaces the real factory entirely
> Explanation: Though often used synonymously, they differ in focus: Virtual Production (Reinhart) is the comprehensive experimentable representation of production processes/facilities via digital models — the vision — created using the methods and tools of the Digital Factory, which itself links real and virtual production.

### Into which three core areas are the elements of the Digital Factory structured?
- [x] Methods, tools and user interfaces (spanning product development and production)
- [ ] Hardware, firmware and cabling
- [ ] Suppliers, producers and customers
- [ ] Push, pull and hybrid
> Explanation: The elements are arranged vertically into methods (functional/organizational tasks and digital representation), tools (computer/software applications, some stand-alone) and user interfaces (direct human-machine coupling, e.g. VR/AR), while horizontally spanning product development and production. Boundaries between the areas are fluid.

### On what data model is process planning based, and what is a key output?
- [x] On the linkage of product, process and resource data (PPR) into a holistic structure; a key output is the Bill of Process (BoP), with the logical sequence defined in a PERT chart
- [ ] On the isolated storage of machine data only, output being a CAD drawing
- [ ] On financial ledgers, output being a balance sheet
- [ ] On the transport matrix only, output being a Sankey diagram
> Explanation: Process planning systems create and manage manufacturing/assembly processes by linking product, process and resource data (PPR) drawn from libraries into a holistic structure tree. Outputs include the Bill of Process (BoP), integrated/centralized data management and a current planning status; the logical PPR sequence is defined graphically in a PERT chart.

### Layout-planning software falls into two groups. Which statements are correct? (Mehrfachauswahl)
- [x] Group 1 offers visualization plus simple optimization, typically based on the triangle-grid diagram and Sankey diagrams (e.g. FactoryFLOW)
- [x] Group 2 implements operations-research optimization methods (e.g. CRAFT, Spiral) to compute an ideal layout
- [x] OR-based methods have low significance in practice because the problem (assigning m machines to n slots) is NP-hard and computationally expensive, so they suit only small problems
- [ ] Digital tools fully automate the final machine layout, making the planner unnecessary
> Explanation: Group 1 = CAD-based visualization with simple optimization via triangle-grid/Sankey; Group 2 = OR algorithms (CRAFT, Spiral) that compute an ideal layout but, being NP-hard and compute-heavy, are rarely used industrially and only for small problems. Because of the many simplifications, the actual machine layout still largely relies on the planner.

### What can Generative AI add to layout planning beyond conventional tools?
- [x] It can propose entirely new layout configurations from high-level requirements, generate multiple feasible scenarios at once, predict load profiles (incl. rare/unseen demand), and be evaluated via simulation
- [ ] It can only evaluate a single fixed layout supplied by the planner
- [ ] It removes the need for any constraints or requirements
- [ ] It guarantees the mathematically optimal layout with no computation
> Explanation: Unlike traditional AI (optimizing within fixed constraints or evaluating fixed alternatives), GenAI proposes new configurations from high-level goals (capacity, material flow, ergonomics), generates several scenarios simultaneously and simulates plausible future demand for robust buffer/energy/utilization planning. Outputs are assessed with simulation models; it is promising but still emerging.

### How does VDI 3633 define simulation, and which guiding principles apply?
- [x] The replication of a system with its dynamic processes in an experimentable model to gain insights transferable to reality; model detail should be "as accurate as necessary" (not "as accurate as possible"), following "simulation before investment"
- [ ] The exact 1:1 physical copy of the real system for destructive testing
- [ ] A static snapshot of the factory with no dynamic behavior
- [ ] A purely financial forecast of investment returns
> Explanation: VDI 3633 defines simulation as replicating a system with its dynamic processes in an experimentable (usually computer) model to gain transferable insights. Studies are run on the model, not the real system; the level of detail follows "as accurate as necessary," and if worthwhile the principle "simulation before investment" applies.

### In a simulation study, which phase can consume up to about 60% of the effort, and what principle governs it?
- [x] Data collection — governed by "do not collect what is possible but collect what is necessary"
- [ ] Model visualization — governed by "as realistic as possible at any cost"
- [ ] The decision for simulation — governed by "always simulate everything"
- [ ] Result interpretation — governed by "ignore implausible results"
> Explanation: A simulation study runs: decide for simulation, define goals, collect data, build the model, run and analyze, implement. Data collection can take up to ~60% of the effort, so the guiding principle is to gather only the necessary data ("do not collect what is possible but collect what is necessary").

### What is the difference between process simulation and motion simulation?
- [x] Process simulation depicts the temporal/capacitive behavior of production systems (bottleneck analysis, buffer/warehouse dimensioning, control strategies); motion simulation depicts kinematic interactions (collision detection, ergonomics, offline robot programming)
- [ ] Process simulation handles robot kinematics; motion simulation handles material-flow throughput
- [ ] Both simulate only the financial performance of the factory
- [ ] Process simulation is static; motion simulation ignores geometry
> Explanation: Process simulation addresses time and capacity behavior — testing control strategies, finding bottlenecks, dimensioning buffers/warehouses, comparing alternatives and "what-if" analyses. Motion (3D) simulation addresses kinematic interactions between components — verifying assembly processes, analyzing ergonomics and detecting collisions (e.g. between welding robots), using geometry, kinematics and control models.

### How do Augmented Reality (AR) and Virtual Reality (VR) differ in factory planning?
- [x] AR overlays virtual, context-relevant information onto the real field of view in real time (e.g. via HMD), keeping the real environment; VR immerses the user in a fully virtual model (e.g. headset or CAVE) with no real surroundings
- [ ] AR fully replaces the real environment; VR only overlays data onto reality
- [ ] Both are identical and used interchangeably
- [ ] AR and VR can only visualize, never support planning or training
> Explanation: AR superimposes information relevant to the user's location/situation onto real objects in real time (data glasses/HMD), e.g. overlaying a planned workstation in the actual workshop or showing assembly instructions in view. VR creates a fully virtual, navigable model (headset/CAVE) for real-size layout review and assembly training outside the real environment. Both raise planning reliability and quality.

### What is the goal of "virtual set-up" (virtual commissioning), and how is it realized?
- [x] To test control programs early by coupling the real control system to a real-time-capable virtual model of the machine via a fieldbus (hardware-in-the-loop), detecting errors during design instead of during set-up — shortening the ramp-up phase
- [ ] To physically assemble the machine twice to compare results
- [ ] To eliminate the control system entirely from the plant
- [ ] To replace all simulation with paper-based planning
> Explanation: In highly automated plants, control software is developed in parallel (simultaneous engineering) but parts can traditionally only be tested during set-up, prolonging ramp-up. Virtual set-up virtualizes the controls during design: the real control system is coupled via a fieldbus to a real-time-capable behavior/visualization model (hardware-in-the-loop), so errors are found earlier and the set-up phase and ramp-up are shortened.
