# Fabrikplanung · VL 07 – Efficiency and Lean Production

### How do Taylorism/Ford mass production and the Toyota Production System (TPS) differ in their approach to the same goal (continuous manufacturing)?
- [x] Ford secured continuous flow with large material/semi-finished buffers and a fixed "one best method"; Toyota used one-piece-flow without buffers, demanding robust processes, and lets any standard be replaced by a better one
- [ ] Both rely on large intermediate buffers and forbid changing standards
- [ ] Toyota uses large buffers; Ford uses one-piece-flow
- [ ] TPS abandons standardization entirely
> Explanation: Ford's mass production (the "first revolution") ensured uninterrupted output via big buffers and Taylor's single best method. Toyota (developed 1950–1985) pursues the same goal via one-piece-flow without intermediate buffers, needing disruption-free processes, and involves employees so any standard can be improved. The IMVP study ("The Machine That Changed the World") triggered the worldwide "second revolution" toward Lean.

### What does the "Toyota House" express about the structure of the TPS?
- [x] Roof = corporate goals (highest quality, lowest cost, shortest lead time); the two pillars = Just-in-Time and Jidoka (autonomous automation); it is only stable if roof, pillars and foundation are stable
- [ ] Roof = Kanban; pillars = 5S and audits; foundation = mass production
- [ ] The house has a single pillar: cost reduction
- [ ] Roof = Just-in-Time; foundation = highest quality only
> Explanation: The Toyota House (coined by Fujio Cho) places the corporate goals — highest quality, lowest cost, shortest lead time — in the roof, supported by the two pillars Just-in-Time and autonomous automation (Jidoka), on a foundation of cost reduction through loss prevention/flexible production. Stability requires all parts to be stable.

### Which statements about the seven wastes (Muda) and the 3M concept are correct? (Mehrfachauswahl)
- [x] The seven wastes are transport, inventory, motion, waiting, overprocessing, overproduction and defects
- [x] Muri means overload/overburden of a machine or employee (causing errors, failures, safety issues)
- [x] Mura means unevenness — alternating periods of overload (Muri) and waste (Muda) from an uneven plan
- [ ] Overproduction is not considered a form of waste in the TPS
> Explanation: Muda (waste) comes in seven forms: transport, inventory, motion, waiting, overprocessing, overproduction, defects. The 3M concept adds Muri (overload) and Mura (unevenness, a mix of Muda and Muri from fluctuating volume). Overproduction is a central waste, countered by leveling (Heijunka) and the pull principle/Kanban.

### What characterizes Just-in-Time (JiT) production in the TPS?
- [x] Each process delivers exactly the demanded quantity at the required time (ideally zero inventory), realized via the pull principle (Kanban); Toyota makes lead time P shorter than the allowed order-to-delivery time D, chiefly by reducing batch sizes
- [ ] JiT builds up large safety stocks to buffer demand fluctuations
- [ ] JiT produces to forecast rather than to consumption
- [ ] JiT requires long set-up times and large batches
> Explanation: JiT means producing the demanded quantity exactly when needed, aiming at zero inventory, using the pull principle so upstream produces only what was consumed. When lead time P exceeds the allowed time D, conventional systems add buffers; Toyota instead shortens P via synchronized production and smaller batches (enabled by SMED).

### What is "autonomous automation" (Jidoka), and why does Toyota accept machine idle time?
- [x] Separation of human and machine: the machine detects abnormalities and stops itself, so one worker can run several machines (multi-machine operation); machine idle is accepted because depreciation lowers a machine's fixed cost over time, while worker cost stays permanently high
- [ ] It means running machines continuously regardless of defects to maximize utilization
- [ ] It keeps a worker permanently monitoring each machine
- [ ] It accepts worker idle time in preference to machine idle time
> Explanation: Jidoka decouples human and machine — the machine stops on abnormalities (building in quality), freeing the worker to operate other machines (multi-machine operation). Toyota tolerates machine waiting over worker waiting: a machine's fixed cost falls through depreciation the longer it is owned, whereas labour cost stays high.

### Under which conditions can a Kanban system be introduced, and how does it work?
- [x] It works via pull: withdrawal of parts from "supermarkets" triggers replenishment; conditions include mass/large-scale production with low demand fluctuation, short set-up times/small batches, flexible skilled workers and low error rates
- [ ] It works via central forecast-driven push scheduling
- [ ] It suits highly complex production with strongly fluctuating demand
- [ ] It requires long set-up times and large batch sizes
> Explanation: A Kanban (card/signal) triggers replenishment of withdrawn parts held in supermarkets (small inter-process buffers); production happens only when a Kanban is present, so buffer stock is capped by the number of Kanbans × container size. Preconditions: mass/large-scale production with low fluctuation, short set-ups, small batches, low error rate, flexible skilled staff.

### Using the classic Kanban formula k = (1 + α)·P·t / B with safety factor α = 0.2, production rate P = 100 units/h, replenishment time t = 2 h and container size B = 40 units, how many containers/Kanbans k are needed?
- [x] k = 6 (1.2 × 100 × 2 / 40 = 240/40)
- [ ] k = 5 (without the safety factor)
- [ ] k = 12 (container size ignored)
- [ ] k = 240 (not divided by container size)
> Explanation: k = (1 + α)·P·t / B = (1 + 0.2) × 100 × 2 / 40 = 1.2 × 200 / 40 = 240/40 = 6 containers. The (1 + α) term adds the safety margin; without it k = 5. The number of circulating Kanbans and the container size together cap the maximum buffer stock.

### Three stations each take 1 min/part, batch of 10 parts, run as one-piece-flow. How long until all 10 parts are finished (and how does this compare to batch production)?
- [x] 12 min in one-piece-flow (3 min for the first part + 9 × 1 min), versus 30 min if the whole batch is processed station by station
- [ ] 30 min in one-piece-flow, the same as batch production
- [ ] 10 min in one-piece-flow
- [ ] 3 min for all 10 parts
> Explanation: In one-piece-flow the first part passes the 3 stations in 3 min, then one further part completes every 1 min → 3 + 9 = 12 min for all 10. In pure batch flow the batch is finished at each station before moving on (10 + 10 + 10 = 30 min), so the first part also appears much later. One-piece-flow thus cuts lead time and inter-process inventory.

### What is the "Takt time," and what happens when it is shortened?
- [x] The time allotted to produce one unit; shortening it requires higher performance per time (more workers/faster machines), while the activities assigned to a takt stay unchanged
- [ ] The total time to produce an entire batch, independent of customer demand
- [ ] The set-up time of a machine between two products
- [ ] The maximum inventory allowed between two stations
> Explanation: Takt time is the time available per unit, set by the customer order situation. Output is adjusted by lengthening/shortening the takt; the work content per takt stays the same, so a shorter takt demands higher performance (e.g. more employees, faster machines). Aligning work content to the takt leads to leveling/smoothing.

### What does Heijunka (production leveling/smoothing) achieve, and how?
- [x] It reduces peaks and raises valleys in the final process so upstream (Kanban-linked) operations are evenly loaded — by leveling monthly/weekly demand into daily quantities, smoothing into sub-quantities, and increasing cycle frequency (smaller batches)
- [ ] It maximizes batch sizes to exploit economies of scale
- [ ] It concentrates all production peaks into a single day
- [ ] It removes the need for any standardized work
> Explanation: Because Kanban links processes backward, fluctuations in the final process burden all upstream operations. Heijunka smooths this: level the monthly/weekly demand into daily quantities, smooth those into sub-quantities, and raise cycle frequency (reduce batch size) — yielding an even load and enabling continuous flow.

### Match the five "S" of the 5S method to their meaning. Which pairings are correct? (Mehrfachauswahl)
- [x] Seiri = Sort (separate needed from unneeded parts and remove the unneeded)
- [x] Seiton = Set in order (place needed parts in clearly defined, easily accessible locations)
- [x] Seiketsu = Standardize (repeat the first three S at frequent intervals to keep the workplace in top condition)
- [ ] Shitsuke = Shine (perform the daily cleaning of machines)
> Explanation: 5S = Seiri (sort), Seiton (set in order), Seiso (shine/clean), Seiketsu (standardize), Shitsuke (sustain — make the first four a habit). Shine is Seiso, not Shitsuke. 5S is regarded as the basis of all continuous improvement.

### What is the purpose and limitation of Poka Yoke?
- [x] Simple, reliable devices on machines/tools that prevent or immediately detect defects (e.g. left-hand gas vs right-hand water thread); they only check quality — quality itself is produced in the operations, so root causes must still be removed via Kaizen
- [ ] Devices that create quality directly and guarantee good parts
- [ ] A metric system for measuring lead time
- [ ] A scheduling method that replaces Kanban
> Explanation: Poka Yoke ("avoiding inadvertent errors") uses simple foolproofing devices to prevent or instantly detect defects — e.g. incompatible gas/water threads prevent mix-ups. They add no value themselves and only check quality; without eliminating the root cause through Kaizen, they cannot sustainably reduce defect-related waste.

### What is the core idea of SMED (Single Minute Exchange of Dies), and its first key step?
- [x] Reducing non-value-adding set-up times to enable small batches and fast response; the first step is separating internal set-up (machine stopped) from external set-up (machine running), then converting internal into external set-up
- [ ] Increasing batch sizes to spread set-up cost over more units
- [ ] Eliminating quality inspection to save time
- [ ] Running set-up only once per year to minimize disruption
> Explanation: SMED cuts changeover time so production can run in small batches with fast demand response (and higher effective machine capacity, lower inventory). Key techniques: separate internal from external set-up (can cut downtime 30–50%), convert internal to external (e.g. preheat dies), standardize function not form, use quick clamps, parallel operations, avoid fine adjustments, mechanize.

### What is Kaizen, and how does the PDCA cycle support it?
- [x] Kaizen = continuous improvement (Kai = change, Zen = for the better); the PDCA cycle (Plan–Do–Check–Act, from the Deming Wheel) standardizes each improvement, and the new state becomes the standard that challenges further improvement
- [ ] Kaizen is a one-time redesign done only at plant commissioning
- [ ] PDCA stands for Plan–Deliver–Control–Audit
- [ ] Kaizen excludes employees from the improvement process
> Explanation: Kaizen is a continuous improvement process resting on the assumption that any system decays unless constantly improved, driven by intensive employee involvement and suggestion systems. PDCA — Plan, Do, Check, Act — is the standardized improvement loop; after each success the new state becomes the standard, and the cycle repeats. Kaizen is considered a prerequisite for the whole TPS.

### How do the vertical and horizontal strategies for introducing a production system differ?
- [x] Vertical: implement at a pilot location/area first, refine from experience, then roll out to other sites. Horizontal: define the whole system theoretically up front, then introduce it simultaneously at all locations on a fixed schedule
- [ ] Vertical means introducing all methods at once everywhere; horizontal means a single pilot area
- [ ] Both strategies forbid a pilot phase
- [ ] The choice is independent of corporate strategy and production structure
> Explanation: Vertical introduction pilots the system in one area, adjusts it, then transfers it; horizontal introduction defines the complete system first and launches it everywhere at once on a fixed timetable. The choice depends on company-specific factors (strategy, process organization, production structure/program). Monden stresses that only holistic (not selective) introduction of the methods yields success.
